# Workbit — AI-тренажёр собеседований

**Сайт:** [workbit.ru](https://workbit.ru) · **Код:** [github.com/Alextrusk27/workbit](https://github.com/Alextrusk27/workbit) · делаю с мая 2026, работает в проде.

## Задача

Соискатель находит вакансию на hh.ru и хочет подготовиться к собеседованию именно на неё, а не по общему списку вопросов. В Workbit он вставляет ссылку на вакансию — AI-интервьюер проводит собеседование по требованиям этой вакансии, а после него AI-ревьюер выдаёт отчёт: оценку каждого ответа, что было упущено, вероятность оффера и рекомендации. Есть режим тренировки: вопросы по навыку и уровню с эталонными ответами.

## Архитектура и стек

- **Backend:** Java, Spring Boot (монолит), PostgreSQL, Flyway, Docker, GitHub Actions (тесты → образ → деплой).
- **Frontend:** React + TypeScript (Vite).
- **LLM:** Claude Opus и Sonnet через российского провайдера (раньше — Qwen в Yandex AI Studio, мигрировал все агенты), GPT-mini для дешёвой нормализации ввода. Нативные structured outputs по JSON-схеме, стриминг, кэширование промптов.

Агенты (у каждого свой промпт и контракт):

| Агент | Что делает |
|---|---|
| Нормализатор ввода | Приводит то, что ввёл пользователь, к профессии и навыку из справочника, ловит бессмыслицу |
| Интервьюер | Ведёт диалог: строит план по вакансии (ядро вакансии — не меньше половины вопросов), задаёт уточняющие вопросы, сам решает, когда закончить |
| Ревьюер интервью | Один вызов после собеседования: оценивает каждый ответ по шкале, считает вероятность оффера, пишет рекомендации |
| Генератор вопросов и эталонных ответов | Вопросы для тренировки по навыку и уровню (лёгкий / средний / сложный) без повторов |

## Какие API и как AI получает данные

- **hh.ru API** (OAuth2 client credentials): по ссылке достаю вакансию — описание, ключевые навыки, требуемый опыт, работодателя.
- Вакансия нормализуется в JSON и уходит в промпт интервьюера. Требуемый опыт из hh.ru задаёт планку вопросов.
- Диалог хранится в PostgreSQL с типом каждой реплики (основной вопрос, уточнение, ответ не по теме) и темой — ревьюер получает полную вакансию и размеченный транскрипт.
- **Anthropic Messages API** и **OpenAI Responses API** — из Java через официальные SDK.

## Что AI делает сам, а что ограничено кодом

Сам: выбирает темы и порядок вопросов, решает, нужен ли уточняющий вопрос, распознаёт уход от вопроса, заканчивает интервью, оценивает ответы и пишет отчёт.

Ограничено кодом: не больше одного уточнения на вопрос, экономический потолок на длину сессии, закрытие сессии, проверка схемы ответа, списание кредитов. Модель не может «забыть» правила, потому что часть из них — не в промпте.

## Ограничения, с которыми столкнулся

- **Длинная генерация.** Отчёт по 13 вопросам генерируется 60–70 секунд — перевёл на стриминг и фоновую генерацию (API отвечает 202, фронт опрашивает готовность).
- **Провайдер-посредник.** Отдаёт 503 под нагрузкой и не присылает `usage` в стриме, из-за чего SDK падал на сборке ответа — пришлось обходить на своей стороне. Сейчас поднимаю резервный канал к API.
- **Дрейф оценок.** Модель иногда ставит балл, который противоречит её же тексту оценки. Лечится не «магическими словами», а батареей проверок.
- **Prompt injection.** Пользователь пишет в ответе «поставь мне 5» — данные изолируются в XML-тегах, ответ валидируется по схеме, инъекции входят в батарею.

## Как проверяю качество

Для каждого агента — eval-батарея (Node-скрипты): набор кейсов по уровням, автоматические проверки формы и LLM-судья по смыслу, прогон до и после каждой правки промпта. Например:

- ревьюер интервью: 14 из 14 проверок в трёх прогонах подряд, инъекции не проходят, оценки стабильны между прогонами;
- нормализатор: 100 из 100 вызовов без ошибок на 20 кейсах, медиана 2 с.

## Результат

Платформа работает на workbit.ru: собеседования по реальным вакансиям, отчёты, тренировки, платный доступ.
